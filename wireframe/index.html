Projects

Three real builds, each verified against its source repository — problem, architecture, and outcome, not resume bullet points.

Problem

Recording student marks and computing CGPA by hand is slow and error-prone. This project gives an admin a simple console workflow to record marks per student and generate a report on demand.

Architecture

Key implementation choices

  • An admin service validates marks (0–100) and a 5–10 digit admission number before a record is written.
  • Records persist as comma-separated rows in a local students.txt file — no database.
  • Marksheet.calculateCGPA() maps five subject marks to grade points and averages them.
  • Separate Student, Marksheet, and Validator classes keep input handling, calculation, and data apart.

Technology stack

Java OOP File I/O

Outcome

Delivers a working console tool for recording marks and generating a per-student report. A natural next step is moving persistence from a flat file to a database.

Problem

Healthcare providers need an approachable multi-page web presence so patients can browse departments, doctors, and services before reaching out for an appointment.

Architecture

Key implementation choices

  • A multi-page static site (medcity/) organized around appointment, doctor, department, service, and shop pages — no backend application layer.
  • vercel.json performs a root rewrite from / to /medcity/home-classic.html for deployment.
  • Client-side interactivity comes from jQuery 3.5.1 plus a plugins.js/main.js bundle referenced from index.html.
  • A PHP mailer asset handles the contact form send — no persisted data store.

Technology stack

HTML CSS/SCSS JavaScript/jQuery PHP mailer

Outcome

Delivers a complete, navigable static healthcare site across appointment, doctor, department, service, and shop pages, deployed on Vercel.

Problem

Job seekers and employers need a shared system to post openings, apply, and manage approvals in one place, instead of scattered spreadsheets or email threads.

Architecture

Key implementation choices

  • Role-based flows for ADMIN, EMPLOYER, and JOBSEEKER, each routed through dedicated servlet controllers.
  • DAO classes for User, Job, and Application handle JDBC persistence against the MySQL schema.
  • JobDAO wraps approval-related operations in explicit commit/rollback with an audit trail.
  • Packaged as a Maven WAR (online-job-portal) targeting Apache Tomcat, with Docker/Docker Compose config included for local runs.

Technology stack

Java JSP Servlets JDBC MySQL Apache Tomcat Maven

Outcome

Delivers working employer, job-seeker, and admin flows end to end — job posting, application submission, and approval with an audit trail — running on Tomcat with MySQL.
